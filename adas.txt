EXPERIMENT 1: Recursive Binary Search + time taken vs n (with graph)
------------------------------------------------------------------------------
Note: The lab file has binary search, but not the timing-vs-n graph. This
version adds it.
Technique: Divide and conquer (decrease and conquer: one half is thrown away each step)
Time complexity:
  - Best case: O(1) (key is the middle element)
  - Average / worst case: O(log n)
  - Recurrence: T(n) = T(n/2) + O(1) => O(log n)
  - Space: O(log n) for the recursion stack (iterative version: O(1))
How it works: Compare the key with the middle element; recurse into the left
or right half. One search is too fast to time, so the program times 10 lakh
searches for each n and divides. Plot n against time per search: it grows like
log n (slowly).

PSEUDOCODE:

Algorithm BinarySearch(A, low, high, key)
    if low > high then
        return -1                               // range empty: not found
    mid <- floor((low + high) / 2)
    if A[mid] = key then
        return mid
    else if key < A[mid] then
        return BinarySearch(A, low, mid - 1, key)    // left half
    else
        return BinarySearch(A, mid + 1, high, key)   // right half

Timing experiment
    for each n in {1000, 5000, 10000, 50000, 100000, 500000, 1000000} do
        A[0..n-1] <- sorted numbers
        start <- clock()
        repeat R times: BinarySearch(A, 0, n - 1, a random key)
        end <- clock()
        print n, (end - start) / R              // time per search
    plot time per search (y) against n (x)

C PROGRAM:

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define MAXN 1000000
#define REPEAT 1000000     /* one search takes far less than a clock tick, so time many */

int a[MAXN], keys[REPEAT];
volatile int sink;         /* stops the compiler from deleting the timed loop */

int binarySearch(int a[], int low, int high, int key) {
    int mid;
    if (low > high)
        return -1;                                   /* empty range: not found */
    mid = (low + high) / 2;
    if (a[mid] == key)
        return mid;
    else if (key < a[mid])
        return binarySearch(a, low, mid - 1, key);   /* search left half */
    else
        return binarySearch(a, mid + 1, high, key);  /* search right half */
}

int main() {
    int sizes[] = {1000, 5000, 10000, 50000, 100000, 500000, 1000000};
    int k, n, i, r, key, pos;
    clock_t start, end;
    double total;

    /* Part 1: normal run on the user's array */
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements in sorted order:\n", n);
    for (i = 0; i < n; i++)
        scanf("%d", &a[i]);
    printf("Enter element to search: ");
    scanf("%d", &key);
    pos = binarySearch(a, 0, n - 1, key);
    if (pos == -1)
        printf("Element not found\n");
    else
        printf("Element found at position %d\n", pos + 1);

    /* Part 2: time taken versus n */
    srand(time(NULL));
    printf("\n%10s %18s %20s\n", "n", "total time (s)", "per search (us)");
    for (k = 0; k < 7; k++) {
        n = sizes[k];
        for (i = 0; i < n; i++)
            a[i] = 2 * i;                            /* sorted even numbers */
        for (r = 0; r < REPEAT; r++)
            keys[r] = 2 * (rand() % n) + 1;          /* odd: never present = worst case */
        start = clock();                             /* time only the searches */
        for (r = 0; r < REPEAT; r++)
            sink = binarySearch(a, 0, n - 1, keys[r]);
        end = clock();
        total = (double)(end - start) / CLOCKS_PER_SEC;
        printf("%10d %18.6f %20.4f\n", n, total, total / REPEAT * 1e6);
    }
    printf("\nPlot n (x-axis) against time per search (y-axis): the curve is log n.\n");
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. What is the condition for using binary search?
A:  The array must be sorted. It also needs random access (an array), so it is
    not used on a linked list.

Q2. What is the time complexity of binary search?
A:  Best case O(1) (key at the middle). Average and worst case O(log n).

Q3. Why log n?
A:  Every step halves the range: n, n/2, n/4, ... 1. After k steps n/2^k = 1,
    so k = log2 n.

Q4. Write its recurrence.
A:  T(n) = T(n/2) + c, which gives O(log n) (master theorem with a = 1, b = 2,
    case 2).

Q5. Space complexity of recursive vs iterative binary search?
A:  Recursive: O(log n) for the recursion stack. Iterative: O(1).

Q6. Which technique is binary search?
A:  Divide and conquer (more exactly decrease and conquer): the problem is
    split in half and only one half is solved.

Q7. Maximum number of comparisons for n = 1000?
A:  floor(log2 1000) + 1 = 9 + 1 = 10.

Q8. Why can mid = (low + high) / 2 be a problem?
A:  For very large indices low + high can overflow an int. Safer: mid = low +
    (high - low) / 2.

Q9. Why do you repeat the search many times when timing it?
A:  One search takes well under a microsecond, less than clock()'s resolution,
    so a single measurement shows 0. Timing many searches and dividing gives
    the average time per search.

Q10. What do clock() and CLOCKS_PER_SEC do?
A:  clock() (in <time.h>) returns the processor time used so far in ticks.
    (end - start) / CLOCKS_PER_SEC converts ticks to seconds.

Q11. What shape does the time vs n graph have?
A:  Logarithmic: it rises very slowly. Doubling n adds only one more
    comparison.

Q12. Linear search vs binary search?
A:  Linear: O(n), works on unsorted data and linked lists. Binary: O(log n),
    needs sorted data with random access.

EXPERIMENT 2: Quick Sort + time taken vs n (with graph)
------------------------------------------------------------------------------
Note: The lab file has quick sort, but not the timing-vs-n graph. This version
adds it.
Technique: Divide and conquer
Time complexity:
  - Best / average case: O(n log n) recurrence T(n) = 2T(n/2) + O(n)
  - Worst case: O(n^2) recurrence T(n) = T(n-1) + O(n); happens on already
  sorted input when the last element is the pivot
  - Space: O(log n) recursion stack on average, O(n) in the worst case
  - Not stable, in-place
How it works: Partition around a pivot (last element): smaller elements go
left, bigger go right, the pivot lands in its final place. Recurse on both
sides. Random input gives the n log n curve.

PSEUDOCODE:

Algorithm QuickSort(A, low, high)
    if low < high then
        p <- Partition(A, low, high)
        QuickSort(A, low, p - 1)
        QuickSort(A, p + 1, high)

Algorithm Partition(A, low, high)
    pivot <- A[high]                            // last element is the pivot
    i <- low - 1
    for j <- low to high - 1 do
        if A[j] < pivot then
            i <- i + 1
            swap A[i] and A[j]
    swap A[i + 1] and A[high]                   // pivot to its final place
    return i + 1

Timing experiment
    for each n in {1000, 5000, 10000, 50000, 100000, 500000} do
        A[0..n-1] <- random numbers
        start <- clock()
        QuickSort(A, 0, n - 1)
        end <- clock()
        print n, end - start
    plot time (y) against n (x)

C PROGRAM:

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define MAXN 500000

int a[MAXN];

int partition(int a[], int low, int high) {
    int pivot = a[high];          /* last element is the pivot */
    int i = low - 1, j, t;
    for (j = low; j < high; j++) {
        if (a[j] < pivot) {
            i++;
            t = a[i]; a[i] = a[j]; a[j] = t;
        }
    }
    t = a[i + 1]; a[i + 1] = a[high]; a[high] = t;
    return i + 1;                 /* pivot's final position */
}

void quickSort(int a[], int low, int high) {
    int p;
    if (low < high) {
        p = partition(a, low, high);
        quickSort(a, low, p - 1);
        quickSort(a, p + 1, high);
    }
}

int main() {
    int sizes[] = {1000, 5000, 10000, 50000, 100000, 500000};
    int k, n, i;
    clock_t start, end;

    /* Part 1: normal run on the user's array */
    printf("Enter number of elements: ");
    scanf("%d", &n);
    printf("Enter %d elements:\n", n);
    for (i = 0; i < n; i++)
        scanf("%d", &a[i]);
    quickSort(a, 0, n - 1);
    printf("Sorted array: ");
    for (i = 0; i < n; i++)
        printf("%d ", a[i]);
    printf("\n");

    /* Part 2: time taken versus n (random input = average case) */
    srand(time(NULL));
    printf("\n%10s %15s\n", "n", "time (s)");
    for (k = 0; k < 6; k++) {
        n = sizes[k];
        for (i = 0; i < n; i++)
            a[i] = rand() % 100000;
        start = clock();
        quickSort(a, 0, n - 1);
        end = clock();
        printf("%10d %15.6f\n", n, (double)(end - start) / CLOCKS_PER_SEC);
    }
    printf("\nPlot n (x-axis) against time (y-axis): the curve is n log n.\n");
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. Who invented quick sort?
A:  Tony (C.A.R.) Hoare, around 1960.

Q2. Which technique does quick sort use?
A:  Divide and conquer. Divide = partition around a pivot; conquer = sort both
    parts recursively; combine = nothing to do (the array is sorted in place).

Q3. Time complexity of quick sort?
A:  Best and average O(n log n); worst O(n^2).

Q4. When does the worst case happen?
A:  When the pivot is always the smallest or largest element, e.g. an already
    sorted or reverse sorted array with the first or last element as pivot.
    One side gets n - 1 elements: T(n) = T(n - 1) + n = O(n^2).

Q5. Recurrence for the best case?
A:  T(n) = 2T(n/2) + n = O(n log n) (the pivot splits the array in half).

Q6. How can the worst case be avoided?
A:  Choose a random pivot, or the median of first, middle and last elements.

Q7. Is quick sort stable? Is it in-place?
A:  Not stable (swaps can change the order of equal elements). In-place: only
    O(log n) recursion stack on average, O(n) worst.

Q8. Which partition scheme does this program use?
A:  Lomuto partition: last element as pivot, one index i marks the end of the
    "smaller than pivot" zone. Hoare's scheme uses two indices moving towards
    each other.

Q9. Quick sort vs merge sort?
A:  Merge sort: always O(n log n), stable, but needs O(n) extra space. Quick
    sort: in-place and usually faster in practice, but O(n^2) in the worst
    case.

Q10. What does srand(time(NULL)) do?
A:  It seeds the random number generator with the current time, so every run
    fills the array with different numbers.

Q11. What shape does the time vs n graph have?
A:  n log n: almost a straight line that bends slightly upward.

EXPERIMENT 5: Nodes reachable from a start node in a digraph, using BFS / DFS
------------------------------------------------------------------------------
Technique: Graph traversal. BFS uses a queue (level by level); DFS uses recursion (a stack, goes deep first)
Time complexity:
  - Adjacency matrix (this code): O(V^2) for both BFS and DFS
  - Adjacency list: O(V + E)
  - Space: O(V) for visited[] and the queue / recursion stack
How it works: Mark the start vertex visited. BFS: take a vertex from the
queue, print it, and enqueue all unvisited neighbours. DFS: print the vertex,
then recursively visit each unvisited neighbour. Every vertex printed is
reachable from the start. adj[i][j] = 1 means an edge i -> j, so the same code
works for a digraph. In the sample, vertex 5 is not reachable.

PSEUDOCODE:

Algorithm BFS(G, s)
    for each vertex v do visited[v] <- false
    visited[s] <- true
    Enqueue(Q, s)
    while Q is not empty do
        v <- Dequeue(Q)
        print v
        for each vertex w with adj[v][w] = 1 do
            if not visited[w] then
                visited[w] <- true              // mark when enqueued
                Enqueue(Q, w)

Algorithm DFS(G, v)
    visited[v] <- true
    print v
    for each vertex w with adj[v][w] = 1 do
        if not visited[w] then
            DFS(G, w)                           // recursion = stack

C PROGRAM:

#include <stdio.h>
#define MAX 20

int adj[MAX][MAX];
int n;
int visited[MAX];

void bfs(int start) {
    int queue[MAX], front = 0, rear = 0;
    int v, i;
    for (i = 0; i < n; i++) visited[i] = 0;
    visited[start] = 1;
    queue[rear++] = start;                 /* enqueue */
    while (front < rear) {
        v = queue[front++];                /* dequeue */
        printf("%d ", v);
        for (i = 0; i < n; i++)
            if (adj[v][i] == 1 && !visited[i]) {
                visited[i] = 1;            /* mark when enqueued */
                queue[rear++] = i;
            }
    }
    printf("\n");
}

void dfs(int v) {
    int i;
    visited[v] = 1;
    printf("%d ", v);
    for (i = 0; i < n; i++)
        if (adj[v][i] == 1 && !visited[i])
            dfs(i);                        /* recursion = implicit stack */
}

int main() {
    int i, j, start;
    printf("Enter number of vertices: ");
    scanf("%d", &n);
    printf("Enter adjacency matrix:\n");
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            scanf("%d", &adj[i][j]);
    printf("Enter start vertex: ");
    scanf("%d", &start);

    printf("\nBFS - nodes reachable from %d: ", start);
    bfs(start);

    for (i = 0; i < n; i++) visited[i] = 0;
    printf("DFS - nodes reachable from %d: ", start);
    dfs(start);
    printf("\n");
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. Which data structure do BFS and DFS use?
A:  BFS uses a queue. DFS uses a stack (or recursion, which uses the call
    stack).

Q2. Time complexity of BFS and DFS?
A:  O(V^2) with an adjacency matrix; O(V + E) with an adjacency list.

Q3. Why is the visited[] array needed?
A:  So that no vertex is processed twice; without it a cycle would make the
    program loop forever.

Q4. Which traversal finds the shortest path in an unweighted graph?
A:  BFS, because it visits vertices in order of the number of edges from the
    start.

Q5. Applications of BFS?
A:  Shortest path in unweighted graphs, level-order traversal, checking if a
    graph is bipartite, finding connected components, web crawlers.

Q6. Applications of DFS?
A:  Topological sorting, cycle detection, strongly connected components, path
    finding, maze solving.

Q7. What is a digraph? How is it stored here?
A:  A directed graph: an edge i -> j does not mean j -> i. adj[i][j] = 1
    stores the edge i -> j.

Q8. How do you find the nodes reachable from a start node?
A:  Run BFS or DFS from that node. Every vertex it visits is reachable; the
    rest are not (vertex 5 in the sample).

Q9. Adjacency matrix vs adjacency list?
A:  Matrix: O(V^2) space, O(1) to test an edge, good for dense graphs. List:
    O(V + E) space, good for sparse graphs.

Q10. Is the BFS / DFS order unique?
A:  No. It depends on the order in which neighbours are checked.

Q11. How are strongly connected components found?
A:  Kosaraju: DFS to get finish times, reverse all edges, then DFS in
    decreasing finish time. Each DFS tree is one SCC. O(V + E).

EXPERIMENT 6: Minimum Cost Spanning Tree using Prim's / Kruskal's algorithm
------------------------------------------------------------------------------
Technique: Greedy
Time complexity:
  - Prim (adjacency matrix, this code): O(V^2); with a binary heap: O(E log V)
  - Kruskal: O(E log E) = O(E log V) (sorting the edges dominates). This code
  uses bubble sort to stay short, which is O(E^2); with qsort / merge sort it
  is O(E log E)
  - Space: O(V) for Prim; O(E + V) for Kruskal (edge list + parent array)
  - An MST of V vertices always has V - 1 edges
How it works: Prim: grow one tree from vertex 0; each step add the cheapest
edge joining the tree to a new vertex. Kruskal: sort all edges by cost and
take each edge that does not make a cycle (checked with union-find: both ends
in the same set means a cycle).

(a) PRIM'S ALGORITHM

PSEUDOCODE:

Algorithm Prim(cost[0..n-1][0..n-1])
    for i <- 0 to n - 1 do
        key[i] <- INF;  inMST[i] <- false
    key[0] <- 0;  parent[0] <- -1;  total <- 0
    repeat n times
        u <- the vertex not in the MST with the smallest key[u]
        if key[u] = INF then report "graph not connected" and stop
        inMST[u] <- true
        total <- total + key[u]
        for each vertex v not in the MST do
            if cost[u][v] < key[v] then
                key[v] <- cost[u][v]            // cheaper way to reach v
                parent[v] <- u
    print edges (parent[v], v) for v = 1 .. n - 1, and total

C PROGRAM:

#include <stdio.h>
#define INF 9999
#define MAX 20

int main() {
    int cost[MAX][MAX], key[MAX], parent[MAX], inMST[MAX];
    int n, i, j, count, min, u, total = 0;
    printf("Enter number of vertices: ");
    scanf("%d", &n);
    printf("Enter cost matrix (0 = no edge):\n");
    for (i = 0; i < n; i++) {
        for (j = 0; j < n; j++) {
            scanf("%d", &cost[i][j]);
            if (cost[i][j] == 0)
                cost[i][j] = INF;
        }
    }
    for (i = 0; i < n; i++) {
        key[i] = INF;
        inMST[i] = 0;
    }
    key[0] = 0;          /* start from vertex 0 */
    parent[0] = -1;

    for (count = 0; count < n; count++) {
        min = INF;
        u = -1;
        for (i = 0; i < n; i++)
            if (!inMST[i] && key[i] < min) {
                min = key[i];
                u = i;
            }
        if (u == -1) {
            printf("Graph is not connected.\n");
            return 0;
        }
        inMST[u] = 1;
        total += key[u];
        for (j = 0; j < n; j++)
            if (!inMST[j] && cost[u][j] < key[j]) {
                key[j] = cost[u][j];
                parent[j] = u;
            }
    }

    printf("Edge   Cost\n");
    for (i = 1; i < n; i++)
        printf("%d - %d   %d\n", parent[i], i, cost[parent[i]][i]);
    printf("Total cost of MST = %d\n", total);
    return 0;
}

(b) KRUSKAL'S ALGORITHM

PSEUDOCODE:

Algorithm Kruskal(G)
    E <- list of all edges (u, v, w)
    sort E by weight w in increasing order
    for each vertex v do parent[v] <- v         // every vertex is its own set
    count <- 0;  total <- 0
    for each edge (u, v, w) in E, in sorted order, while count < n - 1 do
        ru <- Find(u);  rv <- Find(v)
        if ru != rv then                        // different sets: no cycle
            add edge (u, v) to the MST
            parent[ru] <- rv                    // Union
            total <- total + w;  count <- count + 1
    if count < n - 1 then report "graph not connected"

Algorithm Find(v)
    while parent[v] != v do v <- parent[v]
    return v

C PROGRAM:

#include <stdio.h>
#define MAX 20

int parent[MAX];

int find(int v) {                      /* root of v's set */
    while (parent[v] != v)
        v = parent[v];
    return v;
}

int main() {
    int cost[MAX][MAX], eu[MAX * MAX], ev[MAX * MAX], ew[MAX * MAX];
    int n, i, j, m = 0, t, count = 0, total = 0, ru, rv;
    printf("Enter number of vertices: ");
    scanf("%d", &n);
    printf("Enter cost matrix (0 = no edge):\n");
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            scanf("%d", &cost[i][j]);

    /* edge list: each undirected edge once (i < j) */
    for (i = 0; i < n; i++)
        for (j = i + 1; j < n; j++)
            if (cost[i][j] != 0) {
                eu[m] = i; ev[m] = j; ew[m] = cost[i][j]; m++;
            }

    /* sort edges by weight (bubble sort keeps it simple) */
    for (i = 0; i < m - 1; i++)
        for (j = 0; j < m - 1 - i; j++)
            if (ew[j] > ew[j + 1]) {
                t = ew[j]; ew[j] = ew[j + 1]; ew[j + 1] = t;
                t = eu[j]; eu[j] = eu[j + 1]; eu[j + 1] = t;
                t = ev[j]; ev[j] = ev[j + 1]; ev[j + 1] = t;
            }

    for (i = 0; i < n; i++)
        parent[i] = i;                 /* every vertex is its own set */

    printf("Edge   Cost\n");
    for (i = 0; i < m && count < n - 1; i++) {
        ru = find(eu[i]);
        rv = find(ev[i]);
        if (ru != rv) {                /* different sets: no cycle, take it */
            parent[ru] = rv;           /* union */
            printf("%d - %d   %d\n", eu[i], ev[i], ew[i]);
            total += ew[i];
            count++;
        }
    }
    if (count < n - 1)
        printf("Graph is not connected.\n");
    printf("Total cost of MST = %d\n", total);
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. What is a spanning tree?
A:  A subgraph that connects all V vertices with no cycle. It always has
    exactly V - 1 edges.

Q2. What is a minimum cost spanning tree (MST)?
A:  The spanning tree whose total edge cost is the smallest.

Q3. Which technique do Prim and Kruskal use?
A:  Greedy: both add the cheapest safe edge at each step.

Q4. Difference between Prim's and Kruskal's algorithms?
A:  Prim grows one tree from a start vertex, adding the cheapest edge from the
    tree to a new vertex. Kruskal sorts all edges and adds the cheapest edge
    that makes no cycle, joining a forest of trees. Prim suits dense graphs,
    Kruskal sparse ones.

Q5. Time complexity?
A:  Prim: O(V^2) with a matrix, O(E log V) with a binary heap. Kruskal: O(E
    log E) = O(E log V), dominated by sorting.

Q6. How does Kruskal detect a cycle?
A:  With union-find (disjoint sets). If both ends of an edge have the same
    root (same set), adding it would make a cycle.

Q7. Is the MST unique?
A:  It is unique if all edge weights are different. With equal weights there
    may be several MSTs with the same total cost.

Q8. Why is the greedy choice correct?
A:  Cut property: for any cut of the graph, the cheapest edge crossing it
    belongs to some MST.

Q9. Do Prim and Kruskal work with negative edge weights?
A:  Yes. Unlike Dijkstra, MST algorithms have no problem with negative
    weights.

Q10. Can you find an MST of a directed graph with these?
A:  No. They are for undirected connected graphs (the directed version is a
    minimum arborescence).

Q11. What if the graph is not connected?
A:  There is no spanning tree, only a minimum spanning forest. The programs
    print "Graph is not connected".

Q12. Prim vs Dijkstra?
A:  Same structure, different key: Prim's key is the single edge cost to the
    tree; Dijkstra's key is the total distance from the source.

EXPERIMENT 9: 0/1 Knapsack using Backtracking
------------------------------------------------------------------------------
Technique: Backtracking (DFS on the state-space tree, pruning with a bound)
Time complexity:
  - Worst case: O(2^n) nodes (each item is either taken or not), O(n) bound
  per node, so O(n * 2^n)
  - Space: O(n) for the recursion stack and the x[] vector
How it works: Sort items by profit/weight. At level k decide item k: left
child = take it (only if it fits), right child = leave it (only if the bound,
i.e. the fractional-knapsack estimate of the best possible profit, beats the
best answer found so far). The pruning is what makes it faster than trying all
2^n subsets.

PSEUDOCODE:

// items are sorted so that p[1]/w[1] >= p[2]/w[2] >= ... >= p[n]/w[n]
Algorithm BKnap(k, cw, cp)                      // cw = weight so far, cp = profit so far
    if k > n then                               // leaf: every item decided
        if cp > bestProfit then
            bestProfit <- cp;  bestX <- x
        return
    if cw + w[k] <= M then                      // left child: take item k
        x[k] <- 1
        BKnap(k + 1, cw + w[k], cp + p[k])
    if Bound(k + 1, cw, cp) > bestProfit then   // right child: leave item k
        x[k] <- 0
        BKnap(k + 1, cw, cp)

Algorithm Bound(k, cw, cp)                      // fractional-knapsack upper bound
    b <- cp
    for j <- k to n do
        if cw + w[j] <= M then
            cw <- cw + w[j];  b <- b + p[j]
        else
            return b + (M - cw) / w[j] * p[j]   // fraction of item j
    return b

Call: bestProfit <- 0;  BKnap(1, 0, 0)

C PROGRAM:

#include <stdio.h>
#define MAX 20

int n, M;
int p[MAX + 1], w[MAX + 1];
int x[MAX + 1], bestx[MAX + 1];
int bestProfit = 0;
int nodes = 0;

/* upper bound on profit from level k onward: fill by ratio, last item fractionally */
float bound(int k, int cw, int cp) {
    float b = cp;
    int j = k;
    while (j <= n && cw + w[j] <= M) {
        cw += w[j];
        b += p[j];
        j++;
    }
    if (j <= n)
        b += (float)(M - cw) / w[j] * p[j];
    return b;
}

void knap(int k, int cw, int cp) {
    int i;
    nodes++;
    if (k > n) {                       /* leaf: all items decided */
        if (cp > bestProfit) {
            bestProfit = cp;
            for (i = 1; i <= n; i++) bestx[i] = x[i];
        }
        return;
    }
    if (cw + w[k] <= M) {              /* left child: include item k (if it fits) */
        x[k] = 1;
        knap(k + 1, cw + w[k], cp + p[k]);
    }
    if (bound(k + 1, cw, cp) > bestProfit) {   /* right child: exclude, only if promising */
        x[k] = 0;
        knap(k + 1, cw, cp);
    }
}

int main() {
    int i, j, t;
    printf("Enter number of items: ");
    scanf("%d", &n);
    printf("Enter profits:\n");
    for (i = 1; i <= n; i++) scanf("%d", &p[i]);
    printf("Enter weights:\n");
    for (i = 1; i <= n; i++) scanf("%d", &w[i]);
    printf("Enter capacity: ");
    scanf("%d", &M);

    /* sort by profit/weight, largest first */
    for (i = 1; i < n; i++)
        for (j = i + 1; j <= n; j++)
            if (p[j] * w[i] > p[i] * w[j]) {
                t = p[i]; p[i] = p[j]; p[j] = t;
                t = w[i]; w[i] = w[j]; w[j] = t;
            }

    knap(1, 0, 0);

    printf("\nMaximum profit = %d\n", bestProfit);
    printf("Items taken (after sorting by p/w):\n");
    for (i = 1; i <= n; i++)
        if (bestx[i])
            printf("  item %d (p = %d, w = %d)\n", i, p[i], w[i]);
    printf("Nodes visited = %d\n", nodes);
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. What is backtracking?
A:  Building a solution one decision at a time (DFS over the state-space tree)
    and abandoning a branch as soon as it cannot lead to a valid or better
    solution.

Q2. What does the state-space tree look like for 0/1 knapsack?
A:  Level k decides item k: left child = take it (x[k] = 1), right child =
    leave it (x[k] = 0). It has 2^n leaves.

Q3. What is the bounding function?
A:  An upper bound on the profit reachable from a node: current profit +
    greedy fractional filling of the remaining capacity. If the bound is not
    more than the best profit found so far, the branch is pruned.

Q4. Why are the items sorted by profit/weight first?
A:  It makes the fractional bound tight and finds good solutions early, so
    more branches get pruned.

Q5. Time complexity?
A:  Worst case O(2^n) nodes, O(n) bound at each node, so O(n * 2^n). Usually
    far fewer nodes.

Q6. What is the feasibility check?
A:  Take item k only if cw + w[k] <= M.

Q7. Why does greedy fail for 0/1 knapsack?
A:  Items cannot be split. Example: M = 50, items (p, w) = (60, 10), (100,
    20), (120, 30). Greedy by ratio takes the first two = 160; the best is the
    last two = 220.

Q8. Backtracking vs dynamic programming for 0/1 knapsack?
A:  DP is O(nW): fast when the capacity W is small. Backtracking is O(2^n) in
    the worst case, but does not depend on W and works with real-number
    weights.

Q9. Backtracking vs branch and bound?
A:  Backtracking does DFS and prunes with feasibility or bound checks. Branch
    and bound is for optimisation: it generates all children of a node and
    picks the next node by FIFO, LIFO or least cost, killing nodes with
    bounds.

Q10. Is 0/1 knapsack NP-complete?
A:  The decision version is NP-complete. The O(nW) DP is pseudo-polynomial,
    not polynomial.

EXPERIMENT 10: Travelling Salesman Problem using Branch and Bound
------------------------------------------------------------------------------
Technique: LC (least cost) branch and bound with a reduced cost matrix
Time complexity:
  - Worst case: O(n!) nodes (exponential); reducing a matrix is O(n^2) per
  node, so O(n^2 * n!) worst case. In practice far fewer nodes (11 in the
  sample)
  - Space: each live node stores an n x n matrix, so O(n^2) per node
  - Compare: brute force O(n!), DP (Held-Karp) O(n^2 * 2^n)
How it works: Reduce the matrix (subtract row minima, then column minima). The
total subtracted is a lower bound on every tour. For the edge i -> j: set row
i and column j to INF, set [j][1] to INF, reduce again. Child cost = parent
cost + reduced cost(i, j) + new reduction. Always expand the live node with
the least cost; kill nodes whose cost is no better than the best tour. The
sample is the slides example (answer 28).

PSEUDOCODE:

Algorithm TSP_LCBB(C[1..n][1..n])
    root.R <- copy of C;  root.cost <- Reduce(root.R)
    root.path <- (1)
    best <- INF
    add root to the live list
    while the live list is not empty do
        E <- the live node with the least cost  // LC search
        remove E from the live list
        if E.cost >= best then continue         // bound: kill E
        if E.path contains all n cities then
            tour <- cost of E.path + C[last city][1]
            if tour < best then
                best <- tour;  bestPath <- E.path followed by 1
            continue
        i <- last city of E.path
        for each city j not in E.path with E.R[i][j] != INF do   // branch
            M <- copy of E.R
            set row i and column j of M to INF
            M[j][1] <- INF                      // no early return to city 1
            r <- Reduce(M)
            child.R <- M;  child.path <- E.path followed by j
            child.cost <- E.cost + E.R[i][j] + r
            add child to the live list
    return best, bestPath

Algorithm Reduce(M)                             // returns the amount subtracted
    r <- 0
    for each row i do
        m <- minimum of row i
        if m != 0 and m != INF then subtract m from every entry of row i;  r <- r + m
    for each column j do
        m <- minimum of column j
        if m != 0 and m != INF then subtract m from every entry of column j;  r <- r + m
    return r

C PROGRAM:

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAX 10
#define INF 99999

typedef struct {
    int m[MAX][MAX];       /* reduced cost matrix of this node */
    int path[MAX];         /* cities visited so far (0-based) */
    int level;             /* number of edges in the path */
    int city;              /* last city of the path */
    int cost;              /* lower bound for any tour through this path */
} Node;

int n, c[MAX][MAX];
Node *live[200000];         /* live nodes (the LC "queue") */

/* subtract row minima then column minima; return the total subtracted */
int reduce(int m[MAX][MAX]) {
    int i, j, min, r = 0;
    for (i = 0; i < n; i++) {
        min = INF;
        for (j = 0; j < n; j++) if (m[i][j] < min) min = m[i][j];
        if (min != INF && min > 0) {
            for (j = 0; j < n; j++) if (m[i][j] != INF) m[i][j] -= min;
            r += min;
        }
    }
    for (j = 0; j < n; j++) {
        min = INF;
        for (i = 0; i < n; i++) if (m[i][j] < min) min = m[i][j];
        if (min != INF && min > 0) {
            for (i = 0; i < n; i++) if (m[i][j] != INF) m[i][j] -= min;
            r += min;
        }
    }
    return r;
}

int main() {
    Node *e, *ch;
    int nlive = 0, i, j, k, best = INF, bestPath[MAX + 1], visited[MAX], tour, nodes = 0;

    printf("Enter number of cities: ");
    scanf("%d", &n);
    printf("Enter cost matrix (0 on the diagonal / no edge):\n");
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++) {
            scanf("%d", &c[i][j]);
            if (i == j || c[i][j] == 0) c[i][j] = INF;
        }

    /* root: path = {city 1}, cost = reduction of the whole matrix */
    e = malloc(sizeof(Node));
    memcpy(e->m, c, sizeof(c));
    e->path[0] = 0; e->level = 0; e->city = 0;
    e->cost = reduce(e->m);
    live[nlive++] = e;

    while (nlive > 0) {
        /* LC search: take the live node with the least cost */
        k = 0;
        for (i = 1; i < nlive; i++) if (live[i]->cost < live[k]->cost) k = i;
        e = live[k];
        live[k] = live[--nlive];
        nodes++;

        if (e->cost >= best) { free(e); continue; }   /* bound: kill it */

        if (e->level == n - 1) {                      /* complete path: close the tour */
            if (c[e->city][0] != INF) {
                tour = 0;
                for (i = 0; i < n - 1; i++) tour += c[e->path[i]][e->path[i + 1]];
                tour += c[e->city][0];
                if (tour < best) {
                    best = tour;
                    for (i = 0; i < n; i++) bestPath[i] = e->path[i];
                    bestPath[n] = 0;
                }
            }
            free(e);
            continue;
        }

        for (i = 0; i < n; i++) visited[i] = 0;
        for (i = 0; i <= e->level; i++) visited[e->path[i]] = 1;

        for (j = 0; j < n; j++) {                     /* branch: go from e->city to j */
            if (visited[j] || e->m[e->city][j] == INF) continue;
            ch = malloc(sizeof(Node));
            memcpy(ch->m, e->m, sizeof(e->m));
            for (k = 0; k < n; k++) {
                ch->m[e->city][k] = INF;              /* row i = inf */
                ch->m[k][j] = INF;                    /* column j = inf */
            }
            ch->m[j][0] = INF;                        /* no early return to city 1 */
            memcpy(ch->path, e->path, sizeof(e->path));
            ch->level = e->level + 1;
            ch->path[ch->level] = j;
            ch->city = j;
            ch->cost = e->cost + e->m[e->city][j] + reduce(ch->m);
            live[nlive++] = ch;
        }
        free(e);
    }

    if (best == INF) {
        printf("No tour exists.\n");
        return 0;
    }
    printf("\nMinimum tour cost = %d\n", best);
    printf("Tour: ");
    for (i = 0; i <= n; i++)
        printf("%d%s", bestPath[i] + 1, i < n ? " -> " : "\n");
    printf("Nodes expanded = %d\n", nodes);
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. What is the travelling salesman problem?
A:  Find the cheapest tour that visits every city exactly once and returns to
    the starting city.

Q2. Why use branch and bound?
A:  To avoid checking all (n - 1)! tours: lower bounds let whole subtrees be
    killed.

Q3. What is a reduced cost matrix?
A:  A matrix in which every row and every column has at least one 0 (or is all
    INF), made by subtracting row minima, then column minima.

Q4. Why is the reduction amount a lower bound?
A:  Every tour uses exactly one entry from each row and each column.
    Subtracting a constant from a row (or column) lowers every tour by that
    constant, so the total subtracted is at most the cost of any tour.

Q5. Formula for the cost of a child node?
A:  c(child) = c(parent) + R[i][j] + r: parent cost + reduced cost of edge (i,
    j) + reduction of the new matrix.

Q6. Why set row i and column j to INF?
A:  City i has been left and city j has been entered; each happens only once
    in a tour.

Q7. Why set M[j][1] to INF?
A:  So the path cannot return to the start city before visiting all cities.

Q8. What are live node, E-node and dead node?
A:  Live: generated but not yet expanded. E-node: the node being expanded now.
    Dead: killed by the bound or fully expanded.

Q9. LC vs FIFO vs LIFO branch and bound?
A:  They differ in the next E-node: LC takes the least-cost live node, FIFO a
    queue, LIFO a stack.

Q10. Time complexity?
A:  Worst case O(n!) nodes with O(n^2) work each, i.e. exponential; TSP is NP-
    hard.

Q11. Answer for the slides example?
A:  Root cost 25; optimal tour 1 -> 4 -> 2 -> 5 -> 3 -> 1 with cost 28.

Q12. Other ways to solve TSP?
A:  Brute force O(n!); dynamic programming (Held-Karp) O(n^2 * 2^n); nearest-
    neighbour greedy O(n^2) (approximate); MST-based 2-approximation for
    metric TSP.


------------------------------------------------------------------------------
OPEN-ENDED 1 (SN 11): Hamiltonian cycle, and TSP using the Hamiltonian cycle approach
------------------------------------------------------------------------------
Technique: Backtracking
Time complexity:
  - Worst case: O(n!) since there are (n-1)! orderings of the other vertices;
  O(n) check each, so (n-1)! x n = O(n!)
  - Space: O(n) for the path array x[] and the recursion stack
  - Hamiltonian cycle is NP-complete; TSP (decision version) is NP-complete
How it works: Fix city 1 at position 0. At position k try every vertex v that
is adjacent to the previous vertex and not used yet; recurse; undo
(backtrack). When all n are placed and there is an edge back to city 1, it is
a Hamiltonian cycle. TSP answer = cheapest such cycle. (Each cycle is printed
twice, once in each direction.)

PSEUDOCODE:

// x[1..n] holds the cycle; x[1] = 1 (start city)
Algorithm Hamiltonian(k)                        // fill position k
    if k > n then                               // all cities placed
        if edge (x[n], x[1]) exists then        // can return to the start
            print x[1], x[2], ..., x[n], x[1] and its cost
            if cost < best then best <- cost;  bestX <- x
        return
    for v <- 2 to n do
        if IsSafe(v, k) then
            x[k] <- v
            Hamiltonian(k + 1)
            x[k] <- 0                           // backtrack

Algorithm IsSafe(v, k)
    if there is no edge (x[k-1], v) then return false
    if v is already one of x[1..k-1] then return false
    return true

Call: x[1] <- 1;  best <- INF;  Hamiltonian(2)
TSP answer = bestX with cost best (the cheapest Hamiltonian cycle)

C PROGRAM:

#include <stdio.h>
#define MAX 10

int n, g[MAX][MAX], x[MAX];
int count = 0, best = -1, bestx[MAX];

/* can vertex v go at position k of the path? */
int isSafe(int v, int k) {
    int i;
    if (g[x[k - 1]][v] == 0)          /* must be adjacent to the previous vertex */
        return 0;
    for (i = 0; i < k; i++)           /* must not be used already */
        if (x[i] == v)
            return 0;
    return 1;
}

void hamiltonian(int k) {
    int v, i, cost;
    if (k == n) {                                   /* all vertices placed */
        if (g[x[n - 1]][x[0]] != 0) {               /* edge back to start: a cycle */
            cost = 0;
            for (i = 0; i < n - 1; i++) cost += g[x[i]][x[i + 1]];
            cost += g[x[n - 1]][x[0]];
            count++;
            printf("Cycle %d: ", count);
            for (i = 0; i < n; i++) printf("%d -> ", x[i] + 1);
            printf("%d   cost = %d\n", x[0] + 1, cost);
            if (best == -1 || cost < best) {
                best = cost;
                for (i = 0; i < n; i++) bestx[i] = x[i];
            }
        }
        return;
    }
    for (v = 1; v < n; v++) {
        if (isSafe(v, k)) {
            x[k] = v;                               /* place v */
            hamiltonian(k + 1);
            x[k] = -1;                              /* backtrack */
        }
    }
}

int main() {
    int i, j;
    printf("Enter number of cities: ");
    scanf("%d", &n);
    printf("Enter cost matrix (0 = no road):\n");
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            scanf("%d", &g[i][j]);
    for (i = 0; i < n; i++) x[i] = -1;
    x[0] = 0;                                       /* every cycle starts at city 1 */

    printf("\nHamiltonian cycles:\n");
    hamiltonian(1);
    if (count == 0) {
        printf("No Hamiltonian cycle, so no TSP tour.\n");
        return 0;
    }
    printf("\nTSP answer (cheapest Hamiltonian cycle): ");
    for (i = 0; i < n; i++) printf("%d -> ", bestx[i] + 1);
    printf("%d\nMinimum cost = %d\n", bestx[0] + 1, best);
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. What are a Hamiltonian path and a Hamiltonian cycle?
A:  Path: visits every vertex exactly once. Cycle: a Hamiltonian path with an
    edge from the last vertex back to the first.

Q2. Hamiltonian cycle vs Euler circuit?
A:  Hamiltonian: every vertex once. Euler: every edge once. Euler is easy
    (connected and all degrees even); Hamiltonian is NP-complete.

Q3. How does the backtracking work?
A:  Fix vertex 1 first, then fill positions one by one with a vertex that is
    adjacent to the previous one and not used yet. At a dead end, undo the
    last choice (backtrack).

Q4. What does isSafe check?
A:  That v is adjacent to the previous vertex in the path, and that v is not
    already in the path.

Q5. Time complexity?
A:  O(n!) in the worst case: (n - 1)! orderings, O(n) check each.

Q6. How does it solve TSP?
A:  Every TSP tour is a Hamiltonian cycle. Generate all Hamiltonian cycles,
    compute each cost, and take the cheapest.

Q7. Why fix the first vertex?
A:  A cycle can start anywhere; fixing the start avoids listing the same cycle
    n times.

Q8. Why does each cycle appear twice?
A:  In an undirected graph the same cycle is found in both directions.

Q9. Is Hamiltonian cycle NP-complete?
A:  Yes (it is one of Karp's 21 problems). TSP's decision version is NP-
    complete through a reduction from it.

Q10. When is a Hamiltonian cycle guaranteed?
A:  Dirac's theorem: n >= 3 and every vertex has degree >= n/2. Ore's theorem:
    deg(u) + deg(v) >= n for every pair of non-adjacent vertices.

Q11. How many Hamiltonian cycles does a complete graph K_n have?
A:  (n - 1)! / 2 distinct cycles (for n >= 3).


------------------------------------------------------------------------------
OPEN-ENDED 4 (SN 14): Assignment problem (n agents, n tasks, minimum total cost)
------------------------------------------------------------------------------
Technique: Branch and bound (DFS with a lower bound)
Time complexity:
  - Worst case: O(n!) complete assignments; the bound costs O(n^2) per node
  - Space: O(n)
  - Polynomial alternative: Hungarian method, O(n^3)
How it works: Assign agents one by one. Lower bound for a partial assignment =
cost so far + for every remaining agent, its cheapest still-free task. If the
bound is not below the best complete assignment found, prune that branch.
Sample: textbook 4x4 example, answer 13.

PSEUDOCODE:

// agents and tasks are numbered 1..n; c[i][t] = cost of agent i doing task t
Algorithm Assign(a, costSoFar)                  // a = next agent to assign
    if a > n then                               // every agent has a task
        if costSoFar < best then
            best <- costSoFar;  bestAssign <- assign
        return
    for each task t with used[t] = false do
        used[t] <- true;  assign[a] <- t
        if Bound(a + 1, costSoFar + c[a][t]) < best then    // promising?
            Assign(a + 1, costSoFar + c[a][t])
        used[t] <- false                        // backtrack

Algorithm Bound(a, costSoFar)                   // lower bound
    b <- costSoFar
    for i <- a to n do
        b <- b + min { c[i][t] : used[t] = false }
    return b

Call: best <- INF;  Assign(1, 0)

C PROGRAM:

#include <stdio.h>
#define MAX 10
#define INF 99999

int n, c[MAX][MAX];
int assign[MAX], used[MAX];         /* assign[agent] = task; used[task] = 1 if taken */
int best = INF, bestAssign[MAX], nodes = 0;

/* lower bound: cost so far + cheapest free task for every agent not yet assigned */
int bound(int agent, int costSoFar) {
    int i, j, min, b = costSoFar;
    for (i = agent; i < n; i++) {
        min = INF;
        for (j = 0; j < n; j++)
            if (!used[j] && c[i][j] < min) min = c[i][j];
        b += min;
    }
    return b;
}

void solve(int agent, int costSoFar) {
    int j, i;
    nodes++;
    if (agent == n) {                               /* every agent has a task */
        if (costSoFar < best) {
            best = costSoFar;
            for (i = 0; i < n; i++) bestAssign[i] = assign[i];
        }
        return;
    }
    for (j = 0; j < n; j++) {
        if (!used[j]) {
            used[j] = 1;
            assign[agent] = j;
            if (bound(agent + 1, costSoFar + c[agent][j]) < best)   /* promising? */
                solve(agent + 1, costSoFar + c[agent][j]);
            used[j] = 0;                            /* backtrack */
        }
    }
}

int main() {
    int i, j;
    printf("Enter number of agents (= number of tasks): ");
    scanf("%d", &n);
    printf("Enter cost matrix (row = agent, column = task):\n");
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            scanf("%d", &c[i][j]);

    solve(0, 0);

    printf("\nOptimal assignment:\n");
    for (i = 0; i < n; i++)
        printf("  Agent %d -> Task %d   cost %d\n", i + 1, bestAssign[i] + 1, c[i][bestAssign[i]]);
    printf("Minimum total cost = %d\n", best);
    printf("Nodes explored = %d\n", nodes);
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. What is the assignment problem?
A:  n agents and n tasks with a cost for each pair. Give each agent exactly
    one task (one-to-one) so that the total cost is minimum.

Q2. How many possible assignments are there?
A:  n! (every permutation of the tasks).

Q3. What lower bound is used?
A:  Cost so far + for each agent not yet assigned, the cheapest task that is
    still free.

Q4. Why is that bound valid?
A:  Every remaining agent must get some free task, which costs at least its
    cheapest free task.

Q5. Time complexity?
A:  Worst case O(n!) (exponential); pruning usually cuts it a lot. The
    Hungarian method solves it exactly in O(n^3).

Q6. How does the Hungarian method work?
A:  Subtract row minima, then column minima. Cover all zeros with the fewest
    lines. If n lines are needed, an optimal assignment exists among the
    zeros; otherwise subtract the smallest uncovered number from uncovered
    entries, add it at intersections, and repeat.

Q7. Can greedy solve it?
A:  No. Giving each agent its cheapest free task in order can be far from
    optimal.

Q8. Answer for the sample?
A:  Agent 1 -> Task 2, Agent 2 -> Task 1, Agent 3 -> Task 3, Agent 4 -> Task
    4. Total cost 13.

Q9. What if the numbers of agents and tasks differ?
A:  Add dummy agents or tasks with cost 0 to make the matrix square
    (balanced).

Q10. How do you maximise profit instead?
A:  Subtract every entry from the largest entry (or negate the costs) and
    minimise.


------------------------------------------------------------------------------
SN 15: Optimal Binary Search Tree (dictionary words with search frequencies)
------------------------------------------------------------------------------
Technique: Dynamic programming
Time complexity:
  - Time: O(n^3) (n^2 subproblems, each tries up to n roots). With Knuth's
  optimisation: O(n^2)
  - Space: O(n^2) for the e[][], w[][], root[][] tables
How it works: p[i] = probability that word i is searched; q[i] = probability
that a search falls between word i and i+1 (a word with no entry). e[i][j] =
min over root r of e[i][r-1] + e[r+1][j] + w[i][j], where w[i][j] = sum of p
and q in the range. Frequent words end up near the root. Sample = CLRS example
(cost 2.75).

PSEUDOCODE:

// p[1..n] = probability of searching word i
// q[0..n] = probability that a search ends between word i and i+1 (not found)
Algorithm OptimalBST(p, q, n)
    for i <- 1 to n + 1 do
        e[i][i-1] <- q[i-1]                     // empty subtree: one dummy leaf
        w[i][i-1] <- q[i-1]
    for l <- 1 to n do                          // l = number of words in the subtree
        for i <- 1 to n - l + 1 do
            j <- i + l - 1
            e[i][j] <- INF
            w[i][j] <- w[i][j-1] + p[j] + q[j]
            for r <- i to j do                  // try every word as the root
                t <- e[i][r-1] + e[r+1][j] + w[i][j]
                if t < e[i][j] then
                    e[i][j] <- t
                    root[i][j] <- r
    return e[1][n] (minimum expected cost) and root

Algorithm PrintTree(i, j, parent)
    if i > j then return
    r <- root[i][j]
    print word r as the root, or as the left/right child of parent
    PrintTree(i, r - 1, r)
    PrintTree(r + 1, j, r)

float e[MAX + 2][MAX + 1], w[MAX + 2][MAX + 1];

VIVA QUESTIONS AND ANSWERS:

Q1. What is a binary search tree?
A:  A binary tree where every key in the left subtree is smaller than the node
    and every key in the right subtree is larger.

Q2. What is an optimal BST?
A:  The BST with the minimum expected search cost for given search
    probabilities: frequent words near the root, rare ones deeper.

Q3. Why dynamic programming?
A:  Optimal substructure: the subtrees of an optimal BST are optimal for their
    key ranges. Overlapping subproblems: the same ranges i..j are needed again
    and again.

Q4. Write the recurrence.
A:  e[i][j] = min over i <= r <= j of ( e[i][r-1] + e[r+1][j] + w[i][j] ),
    with e[i][i-1] = q[i-1].

Q5. What is w[i][j] and why is it added?
A:  w[i][j] = p[i] + ... + p[j] + q[i-1] + ... + q[j]. When a subtree goes one
    level deeper under a root, every search in it costs one more comparison.

Q6. What are the q values (dummy keys)?
A:  Probabilities of unsuccessful searches: searching for a word that is not
    in the dictionary and falls between two keys.

Q7. Time and space complexity?
A:  O(n^3) time and O(n^2) space. Knuth's optimisation (root[i][j-1] <=
    root[i][j] <= root[i+1][j]) gives O(n^2).

Q8. Why not just put the most frequent word at the root (greedy)?
A:  That does not always give the minimum expected cost; DP checks every
    possible root.

Q9. How many different BSTs can n keys form?
A:  The Catalan number C(n) = (2n)! / ((n + 1)! n!), which grows
    exponentially, so brute force is impossible.

Q10. Answer for the sample?
A:  Expected cost 2.75 with "is" (key 2) as the root. This is the CLRS
    textbook example.


------------------------------------------------------------------------------
SN 16: String matching for plagiarism detection: Naive, KMP, Rabin-Karp
------------------------------------------------------------------------------
Technique: String matching (n = text length, m = pattern length)
Time complexity:
  - Naive: worst O((n - m + 1) * m) = O(nm); best O(n). Space O(1)
  - KMP: O(n + m) always (O(m) to build the LPS table + O(n) search; text
  pointer never moves back). Space O(m)
  - Rabin-Karp: average O(n + m); worst O(nm) when many hash values collide
  (spurious hits). Space O(1)
  - Recommendation for large-scale plagiarism detection: KMP for one pattern
  (guaranteed linear); Rabin-Karp when searching many patterns at once
  (compare hashes)
How it works: Naive tries every shift. KMP precomputes lps[] (the longest
proper prefix of the pattern that is also a suffix), so after a mismatch it
shifts the pattern without re-reading text. Rabin-Karp compares a rolling hash
of the window with the pattern's hash and checks the characters only when the
hashes match. Part 2 times all three on texts of 10^4, 10^5, 10^6 characters
(naive's bad case: "aaa...ab").

PSEUDOCODE:

// T[0..n-1] = text, P[0..m-1] = pattern
Algorithm NaiveMatch(T, P)
    for s <- 0 to n - m do                      // every shift
        j <- 0
        while j < m and T[s + j] = P[j] do j <- j + 1
        if j = m then print "match at", s

Algorithm ComputeLPS(P)                         // lps[i] = longest proper prefix = suffix of P[0..i]
    lps[0] <- 0;  len <- 0;  i <- 1
    while i < m do
        if P[i] = P[len] then
            len <- len + 1;  lps[i] <- len;  i <- i + 1
        else if len != 0 then
            len <- lps[len - 1]
        else
            lps[i] <- 0;  i <- i + 1

Algorithm KMPMatch(T, P)
    ComputeLPS(P)
    i <- 0;  j <- 0
    while i < n do
        if T[i] = P[j] then
            i <- i + 1;  j <- j + 1
            if j = m then
                print "match at", i - j
                j <- lps[j - 1]                 // continue for overlapping matches
        else if j != 0 then
            j <- lps[j - 1]                     // i never moves back
        else
            i <- i + 1

Algorithm RabinKarp(T, P, d, q)                 // d = alphabet size, q = a prime
    h <- d^(m-1) mod q
    p <- 0;  t <- 0
    for i <- 0 to m - 1 do
        p <- (d * p + P[i]) mod q               // hash of the pattern
        t <- (d * t + T[i]) mod q               // hash of the first window
    for s <- 0 to n - m do
        if p = t then                           // hashes equal: check characters
            if T[s .. s+m-1] = P[0 .. m-1] then print "match at", s
        if s < n - m then                       // roll the hash one step right
            t <- (d * (t - T[s] * h) + T[s + m]) mod q
            if t < 0 then t <- t + q

C PROGRAM:

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>

#define MAXT 1000001
#define MAXP 1000
#define D 256          /* alphabet size for Rabin-Karp */
#define Q 101          /* a prime for the hash */

char text[MAXT], pat[MAXP];
int lps[MAXP];
int show = 1;          /* print match positions (off during timing) */

int naive(char *t, char *p) {
    int n = strlen(t), m = strlen(p), i, j, count = 0;
    for (i = 0; i <= n - m; i++) {            /* try every shift */
        for (j = 0; j < m && t[i + j] == p[j]; j++);
        if (j == m) {
            count++;
            if (show) printf("%d ", i);
        }
    }
    return count;
}

void computeLPS(char *p, int m) {             /* longest proper prefix that is also a suffix */
    int len = 0, i = 1;
    lps[0] = 0;
    while (i < m) {
        if (p[i] == p[len]) lps[i++] = ++len;
        else if (len != 0) len = lps[len - 1];
        else lps[i++] = 0;
    }
}

int kmp(char *t, char *p) {
    int n = strlen(t), m = strlen(p), i = 0, j = 0, count = 0;
    computeLPS(p, m);
    while (i < n) {
        if (t[i] == p[j]) {
            i++; j++;
            if (j == m) {
                count++;
                if (show) printf("%d ", i - j);
                j = lps[j - 1];               /* keep going for overlapping matches */
            }
        } else if (j != 0) {
            j = lps[j - 1];                   /* never move i backwards */
        } else {
            i++;
        }
    }
    return count;
}

int rabinKarp(char *t, char *p) {
    int n = strlen(t), m = strlen(p), i, j, h = 1, ph = 0, th = 0, count = 0;
    if (m > n) return 0;
    for (i = 0; i < m - 1; i++) h = (h * D) % Q;            /* D^(m-1) mod Q */
    for (i = 0; i < m; i++) {
        ph = (D * ph + p[i]) % Q;
        th = (D * th + t[i]) % Q;
    }
    for (i = 0; i <= n - m; i++) {
        if (ph == th) {                                       /* hash match: check characters */
            for (j = 0; j < m && t[i + j] == p[j]; j++);
            if (j == m) {
                count++;
                if (show) printf("%d ", i);
            }
        }
        if (i < n - m) {                                      /* roll the hash one step */
            th = (D * (th - t[i] * h) + t[i + m]) % Q;
            if (th < 0) th += Q;
        }
    }
    return count;
}

int main() {
    int sizes[] = {10000, 100000, 1000000};
    int k, i, n, c1, c2, c3;
    clock_t s;
    double t1, t2, t3;

    /* Part 1: the user's text and pattern */
    printf("Enter text: ");
    fgets(text, MAXT, stdin);
    text[strcspn(text, "\n")] = '\0';
    printf("Enter pattern: ");
    fgets(pat, MAXP, stdin);
    pat[strcspn(pat, "\n")] = '\0';

    printf("\nNaive      matches at: "); c1 = naive(text, pat);     printf(" (%d found)\n", c1);
    printf("KMP        matches at: "); c2 = kmp(text, pat);       printf(" (%d found)\n", c2);
    printf("Rabin-Karp matches at: "); c3 = rabinKarp(text, pat); printf(" (%d found)\n", c3);

    /* Part 2: timing on texts of different sizes.
       Text of 'a's with a rare 'b', pattern "aaa...ab": naive's worst case. */
    show = 0;
    for (i = 0; i < 99; i++) pat[i] = 'a';
    pat[99] = 'b'; pat[100] = '\0';
    printf("\n%10s %12s %12s %12s   (seconds, pattern length 100)\n", "text size", "Naive", "KMP", "Rabin-Karp");
    for (k = 0; k < 3; k++) {
        n = sizes[k];
        for (i = 0; i < n; i++) text[i] = (i % 1000 == 999) ? 'b' : 'a';
        text[n] = '\0';
        s = clock(); c1 = naive(text, pat);     t1 = (double)(clock() - s) / CLOCKS_PER_SEC;

    }
    return 0;
}

VIVA QUESTIONS AND ANSWERS:

Q1. Time complexity of naive string matching?
A:  O((n - m + 1) * m) = O(nm) in the worst case, e.g. text "aaaa...a" and
    pattern "aa...ab". Best case O(n).

Q2. Time complexity of KMP?
A:  O(n + m): O(m) to build the LPS table plus O(n) to scan the text. The text
    pointer never moves back.

Q3. What is the LPS (prefix function) array?
A:  lps[i] = length of the longest proper prefix of P[0..i] that is also a
    suffix of it. Example: "AABAACAABAA" gives 0 1 0 1 2 0 1 2 3 4 5.

Q4. How does KMP avoid re-checking characters?
A:  After a mismatch at pattern position j, it continues from j = lps[j - 1]
    because that much of the pattern is already known to match.

Q5. Time complexity of Rabin-Karp?
A:  Average O(n + m); worst O(nm) when many windows have the same hash as the
    pattern.

Q6. What is a spurious hit?
A:  The window's hash equals the pattern's hash but the characters differ.
    That is why characters are checked after a hash match.

Q7. How is the rolling hash updated?
A:  t = (d * (t - T[s] * h) + T[s + m]) mod q, where h = d^(m-1) mod q. It
    costs O(1) per shift.

Q8. Why take the hash mod a prime q?
A:  It keeps the numbers small and spreads hash values evenly, so there are
    fewer collisions.

Q9. Which algorithm would you recommend for plagiarism detection?
A:  For one pattern, KMP (guaranteed linear time). To compare many phrases at
    once, Rabin-Karp: hash all k-word windows of both documents and compare
    the hashes (fingerprinting, as tools like MOSS do). Naive only for small
    inputs.

Q10. Space complexity?
A:  Naive O(1), KMP O(m) for the LPS array, Rabin-Karp O(1).

Q11. Who designed KMP and Rabin-Karp?
A:  KMP: Knuth, Morris and Pratt (1977). Rabin-Karp: Michael Rabin and Richard
    Karp (1987).

Q12. Other string matching algorithms?
A:  Boyer-Moore (skips ahead, very fast in practice), Aho-Corasick (many
    patterns at once), Z-algorithm.

EXPERIMENT 3: Knapsack problem using the greedy approach (fractional knapsack)
[lab file Program 6]
------------------------------------------------------------------------------
Time complexity: O(n log n) for sorting by profit/weight; the filling loop is
O(n).

VIVA QUESTIONS AND ANSWERS:

Q1. What is the greedy choice?
A:  Take items in decreasing order of profit/weight. Take whole items while
    they fit, then a fraction of the next one.

Q2. Why does greedy give the optimal answer here?
A:  Items can be split, so the capacity can always be filled with the best
    ratios available. Each unit of weight carries the highest possible profit.

Q3. Why does greedy not work for 0/1 knapsack?
A:  A high-ratio item can leave wasted capacity that cannot be filled. M = 50,
    (60, 10), (100, 20), (120, 30): greedy 160, optimal 220.

Q4. Work out the example M = 50, (60, 10), (100, 20), (120, 30).
A:  Ratios 6, 5, 4. Take items 1 and 2 whole (profit 160, weight 30), then
    20/30 of item 3 (profit 80). Total 240.

Q5. How many items can be fractional in the optimal solution?
A:  At most one: the last item taken.

Q6. Why sort by ratio, not by profit or by weight?
A:  Highest profit first can fill the bag with heavy items; lightest first can
    pick worthless items. Only the ratio is always optimal.

Q7. What two properties make a greedy algorithm correct?
A:  Greedy choice property (a locally best choice is part of an optimal
    solution) and optimal substructure.

Q8. Fractional vs 0/1 knapsack methods?
A:  Fractional: greedy. 0/1: dynamic programming, backtracking or branch and
    bound.

EXPERIMENT 4: 0/1 Knapsack using dynamic programming  [lab file Program 9]
------------------------------------------------------------------------------
Time complexity: O(nW) time and space (n items, capacity W); pseudo-
polynomial.

VIVA QUESTIONS AND ANSWERS:

Q1. Write the recurrence.
A:  K[i][w] = K[i-1][w] if w[i] > w; otherwise K[i][w] = max( K[i-1][w], p[i]
    + K[i-1][w - w[i]] ).

Q2. What are the base cases?
A:  K[0][w] = 0 (no items) and K[i][0] = 0 (no capacity).

Q3. Why is it called pseudo-polynomial?
A:  O(nW) depends on the value of W, not on the number of bits needed to write
    W. A huge W makes it slow.

Q4. How do you find which items were taken?
A:  Trace back from K[n][W]: if K[i][w] != K[i-1][w], item i was taken, so set
    w = w - w[i]. Then go to row i - 1.

Q5. How can the space be reduced?
A:  Use one array of size W + 1 and loop w from W down to w[i]: O(W) space.

Q6. Why is dynamic programming used?
A:  Optimal substructure plus overlapping subproblems: the same (item,
    capacity) pairs repeat, so each answer is stored once.

Q7. Answer for M = 50, (60, 10), (100, 20), (120, 30)?
A:  220, by taking items 2 and 3.

Q8. DP vs divide and conquer?
A:  Both split into subproblems. DP subproblems overlap, so results are stored
    in a table; D&C subproblems are independent.

Q9. Is 0/1 knapsack NP-complete?
A:  Its decision version is NP-complete. The DP does not contradict this
    because it is pseudo-polynomial.

EXPERIMENT 7 and SN 13: Dijkstra's shortest paths (road network)  [lab file
Program 7]
------------------------------------------------------------------------------
Time complexity: O(V^2) with an adjacency matrix; O((V + E) log V) with a
binary heap.

VIVA QUESTIONS AND ANSWERS:

Q1. What does Dijkstra find?
A:  Shortest distances from one source vertex to every other vertex, in a
    graph with non-negative edge weights.

Q2. Which technique is it?
A:  Greedy: each step finalises the unvisited vertex with the smallest
    distance, then relaxes its edges.

Q3. What is relaxation?
A:  If d[u] + w(u, v) < d[v], then set d[v] = d[u] + w(u, v) and parent[v] =
    u.

Q4. Why does Dijkstra fail with negative edges?
A:  A vertex is final once picked. A negative edge found later could give it a
    shorter path, which Dijkstra never revisits. Use Bellman-Ford, O(VE).

Q5. How do you print the actual path?
A:  Store parent[v] during relaxation, then follow parents from the
    destination back to the source.

Q6. Dijkstra vs Floyd-Warshall?
A:  Dijkstra: single source, O(V^2). Floyd-Warshall: all pairs, O(V^3), and it
    allows negative edges (but not negative cycles).

Q7. Dijkstra vs Prim?
A:  Same structure; Dijkstra's key is the total distance from the source,
    Prim's key is the one edge to the tree.

Q8. How does SN 13 (road network) map to this?
A:  Junctions = vertices, road segments = edges, weight = length, time or cost
    (all positive), one-way streets = directed edges. So Dijkstra applies
    directly.

Q9. What do real map apps add?
A:  A* search (a distance estimate to the goal) and contraction hierarchies,
    which make important roads (highways) shortcuts. That is the "some edges
    are more important" idea.

Q10. Why is INF used, and what is the risk?
A:  INF marks "not reached yet". Choose it so INF + weight does not overflow
    an int (e.g. 9999 for small graphs).

EXPERIMENT 8: N-Queens using backtracking  [lab file Program 11]
------------------------------------------------------------------------------
Time complexity: O(N!) in the worst case.

VIVA QUESTIONS AND ANSWERS:

Q1. State the problem.
A:  Place N queens on an N x N board so that no two share a row, column or
    diagonal.

Q2. How does backtracking solve it?
A:  Place one queen per row. Try each column; if it is safe, go to the next
    row. If no column works, go back and move the previous queen.

Q3. Write the safety check.
A:  For every earlier row k: x[k] == col (same column) or abs(x[k] - col) ==
    abs(k - row) (same diagonal) means unsafe.

Q4. Why one queen per row?
A:  Two queens in one row would attack each other, so the row is fixed by the
    level of the tree and only the column is chosen.

Q5. How many solutions are there?
A:  4-queens: 2, (2, 4, 1, 3) and (3, 1, 4, 2). 8-queens: 92 (12 distinct up
    to rotation and reflection). N = 2 and N = 3: none.

Q6. What is the state-space tree?
A:  Level = row, each branch = a column for that row's queen. Unsafe branches
    are pruned immediately.

Q7. Why not brute force?
A:  There are C(64, 8), about 4.4 billion, ways to place 8 queens.
    Backtracking rejects a partial board as soon as two queens attack.

Q8. Explicit vs implicit constraints?
A:  Explicit: x[i] is in {1..N}. Implicit: no two queens attack each other.

SN 12 (open-ended 2): Longest Common Subsequence using DP  [lab file Program 8
/ OE 2]
------------------------------------------------------------------------------
Time complexity: O(mn) time and space (m, n = string lengths).

VIVA QUESTIONS AND ANSWERS:

Q1. Subsequence vs substring?
A:  A subsequence keeps the order but need not be contiguous; a substring must
    be contiguous.

Q2. Write the recurrence.
A:  c[i][j] = c[i-1][j-1] + 1 if X[i] = Y[j]; otherwise max(c[i-1][j],
    c[i][j-1]). c[0][j] = c[i][0] = 0.

Q3. How do you print the LCS itself?
A:  Start at c[m][n]. If the characters match, record it and go diagonally up-
    left; otherwise move to the larger of up and left.

Q4. Brute force complexity?
A:  O(n * 2^m): a string of length m has 2^m subsequences.

Q5. Can the space be reduced?
A:  For the length only, keep two rows: O(min(m, n)). The full table is needed
    to print the sequence.

Q6. Applications?
A:  diff / file comparison, version control, DNA sequence alignment
    (bioinformatics), plagiarism detection.

Q7. Is the LCS unique?
A:  The length is unique; the sequence may not be.

Q8. Lab file samples?
A:  ABCDGH and AEDFHR give ADH (length 3). AGGTAB and GXTXAYB give GTAB
    (length 4).

SN 17 (open-ended 1): Minimum currency notes using greedy  [lab file OE 1]
------------------------------------------------------------------------------
Time complexity: O(k log k) to sort k denominations, then O(k) using division
(or one step per note).

VIVA QUESTIONS AND ANSWERS:

Q1. What is the greedy rule?
A:  Repeatedly take the largest note that is not more than the remaining
    amount.

Q2. Is greedy always optimal?
A:  Only for "canonical" systems like Indian currency. For {10, 40, 60} and
    80, greedy gives 60 + 10 + 10 (3 notes); the best is 40 + 40 (2 notes).

Q3. Can greedy fail completely?
A:  Yes. For {20, 30, 50} and 90, greedy takes 50 + 30 and cannot make the
    last 10, but 30 + 30 + 30 works.

Q4. Which method is always correct?
A:  Dynamic programming: dp[a] = min over notes d <= a of dp[a - d] + 1, with
    dp[0] = 0. O(kA) time.

Q5. Answer for 289 with Indian notes?
A:  100 + 100 + 50 + 20 + 10 + 5 + 2 + 2 = 8 notes.

Q6. Why does greedy work for Indian currency?
A:  Each denomination is "big enough" relative to the smaller ones that using
    a larger note never needs more notes in total (a canonical coin system).
